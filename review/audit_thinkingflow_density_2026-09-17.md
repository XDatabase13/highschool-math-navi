## 0. 結論の要約

- 3単元の差は「単元特性」と「制作時期の設計ドリフト」の**両方**で、しかも文字数の平均差はドリフトの方が大きい。
- 仮説（細かく分割すれば総説明量が増えても認知負荷は増えない）は**条件付きで正しい**。正しくなる条件は「増える説明が"判断とその根拠"であること」。結果の言い直し・手順の語り・見出しの反復で増えた分は、分割しても負荷にしかならない。
- このサービスに合う方向は、三角比・二次関数・データの分析のどれか1つではなく、**「三角比の式中心の骨格」＋「二次関数の一文（何を・なぜ）」＋「データの分析が判断問題で書いている判断文」**の合成。既存の中で最も近いのはTR-022／QF-038／DA-013。
- 提案する設計原則：**「1Flow＝1判断。本文には、その判断を生徒がその場で再現するのに必要なものだけを書く」**（第6節）。

## 2. 通読で見えた密度の型

文字数ではなく「ステップの中身」で分類すると、118問のFlowは次の型に分かれる。

### 2.1 適正：1判断＋その場で必要な根拠

- **TR-022 #3**「正弦定理でBを求める」：式 → sin B=√2/2 → 「A=120°よりB<60°なので」→ B=45°。判断（2候補から1つを選ぶ）と、その根拠が1文。読者はこの1文で次に進める。
- **QF-038 #3**：「D>0 ⟺ a<2 より、a<2のとき共有点は2個」を3行並べただけ。式だけで理解でき、余計な語りがない。
- **QF-046 #4**：数直線の共通部分を読むステップに「√5≈2.236なので、3<xの部分は重ならない」。ここが中間層の落とし穴であり、その1文だけが足されている。
- **DA-013 (2)#2**：分散が小さくなる理由を「19→18で平均からの距離が小さくなり、10→11でも小さくなる。したがって偏差の2乗は全体として小さくなる」。計算せずに判断する問題なので、文章が骨格そのものになっている。
- **TR-010 (1)#1**：「sinθ>0となるのは第1・第2象限なので、cosθの符号は正・負の両方があり得る」。符号判断の根拠として過不足がない。
- **QF-028 #2**：「積が0になるのは、2つの因数のうち少なくとも一方が0になるときである」。土台問題（難1）で、このレベルの生徒にはこの1文が橋渡しになる。

共通点：**ステップの中に判断が1つだけあり、本文はその判断の根拠か、判断の結果を式にしたものだけ**。見出しを言い換えた文がない。

### 2.2 薄すぎ：判断や計算の"飛び"が見えない

- **TR-036 (1)#1「AC, AF, CFを求める」**：本文が `AC=3, AF=√13, CF=4` のみ。どの面のどの直角三角形に三平方を使ったかが無い。(2)#1「面積を求める」も `S=3√3` のみ、(3)#1「体積を求める」も `V=√5` のみ。**Flowが"考え方"ではなく"答えの一覧"になっている**。この問題は問題メタで「空間図形で一番最初に押さえておきたい」「本問題を押さえずに他を優先するのは考えづらい」と位置づけられた本命問題であり、最も薄くてはいけない箇所が最も薄い。TR-037#1（`AP=2√7, AQ=2√7, PQ=2√3`）、TR-038 (1)#2（`cosα=1/3`）、(3)#1（`S=9√3`）、TR-039 (1)#2 も同型。
- **TR-016 (1)#2「計算する」**：`a/sin30°=6/sin45°` の次が `a=3√2`。解法メタが「分数の中に分数が出てきたら斜めに掛け算…具体的には各Flowを見てください」と案内しているのに、Flowにその計算が無い。**メタがFlowに約束したものをFlowが果たしていない**。TR-018 #2（`a²=4`へ一足飛び）も同じ。
- **TR-019 #3「☆☆ 答えと図を確認する」**：「a=2とa=4は、どちらも実際に三角形を作ることができる」。☆☆の判断ステップなのに、なぜ両方採用できるのかの根拠が無い（この問題は片方を捨てる場合との対比が肝）。
- **QF-047 #3／QF-048 #3「⚠ 必要なら D の簡易グラフを描く」**：本文が#1と同じ式の再掲だけ。開いても何も得られないステップ。
- **見出しの反復だけのステップ**：QF-007 #1（見出し「平方完成する」→本文「平方完成する。」）、QF-009 #3、QF-025 #3、QF-026 #4、QF-027 #3。式は正しいが、本文が情報を足していない。

共通点：**開くコストに見合う中身がない**。UIが1ステップずつ開閉する構造だからこそ、「開いたのに結果しか無い」「開いたのに見出しと同じ」は通常の解説より目立つ。

### 2.3 濃すぎ：判断のない文章で膨らんでいる

- **二重記述（二次関数 013〜020）**：QF-014 #2「頂点(2,−3)をもとに、下に凸の放物線をざっと描く。／下に凸で、頂点は(2,−3)。」。同じ内容を2行で書いている。QF-013 #2、015 #2、016 #2〜#3、020 (1)#2〜#3・(2)#2〜#3 も同型。これは人間が固定した骨格行（「下に凸で、頂点は(2,−3)。」）を残したまま、教材化時に説明文を上に足した痕跡で、**単元特性ではなく制作工程の産物**。
- **手順の語り（QF-021）**：(1)#4「③で分けた3つの場合それぞれに、②で確認した『頂点が中にあれば頂点…』という関係を当てはめる」。前ステップの内容をもう一度述べてから当てはめると宣言している。(2)#2は「定義域の両端のうち頂点から遠い方」を3回言い換えている。QF-020 (1)#3〜#4「①で求めた…③で求めた最小値をmと名付ける」も同じ語り口。**手順番号を使った自己参照は、思考ではなく進行の説明**。
- **判断ゼロの算術を独立Flowにする（DA-012）**：(2)#2「A群・B群それぞれのx²の合計」＝`8×19=152, 12×89=1068`、#3「全体のx²の合計」＝`152+1068=1220`。掛け算と足し算が1ステップずつ。解法メタの「各群の統計量→合計→全体の合計→全体の統計量」という流れを忠実に写しているので意図は分かるが、開くたびに得られるのは掛け算の答えだけになっている。
- **結論の言い直し（データの分析全般）**：DA-010 #3「=7 ／ したがって、分散は7。」、#4「√7 ／ したがって、標準偏差は√7。」、DA-011・016も同じ。式が既に答えを示している直後に日本語で繰り返している。1問では気にならないが、23問で全ステップに付くと「読み飛ばす行」が定着する。
- **検証の重複（DA-005 #3）**：候補比較の表（レビューで追加した部分）で結論が出た後に、同じ2.5→3.1の場合をもう一度並べて検算している。表の行と重複しており、表を入れた時点で後半は半分に削れた。これは今回の制作側の判断ミスとして明記する。

共通点：**増えた分に判断が含まれていない**。分割してもこの部分の負荷は下がらない。

### 2.4 「必要な橋渡しとして詳しい」と「通常解説化」の線引き

同じ「文章が長い」でも、次の区別で扱いが変わる。

| 橋渡し（残す） | 解説化（削る／移す） |
|---|---|
| 符号・候補の採否・場合分けの境目など、**その場で下す判断の根拠** | 前ステップで既に述べたことの再説明 |
| 中間層が一段で飛べない**計算の中間1行**（分数の分数、二次方程式化） | 手順番号での自己参照（「②で確認した…」） |
| 「最も長い辺に対する角が最も大きい」のような、**そのステップで初めて使う原理1文** | 用語の定義や背景理論（→問題メタ・解法メタ） |
| 選択肢判定・訂正データ特定など、**判断そのものが文章になる問題**の判断文 | 式が既に示している結果の日本語での言い直し |
| データの分析の表（偏差表・候補表）：判断を一覧化する道具 | 別解・確認ルート（→補助Flow か 解法メタ） |

DA-020〜021（仮説検定）でFlow内に「このように最初に置く仮説を帰無仮説という」と定義が入っているのは、問題自体が「手順を体験する」問題なので橋渡し側。ただしこれが許されるのは問題の主題が手順そのものである場合に限る。

## 3. 単元特性か、制作時期のドリフトか

### 3.1 単元特性として正当な差（維持してよい）

- **図形問題（三角比）は式で追える**：「余弦定理を立てる→解く」は式2本で完結し、文章は判断（2解の採否、鈍角の符号）にだけ要る。散文ゼロのステップが一定数あるのは自然。
- **判断問題（データの分析の 008・009・013・018・020〜023）は文章が骨格**：ここで式だけにすると「答え」しか残らない。
- **場合分け問題（二次関数の 017・018・021・052・053・054）は「どの場合か」を言葉で言う必要がある**：グラフを見て境目を決める判断は式にならない。

### 3.2 制作時期のドリフト（基準がなかったことの結果）

制作工程は3回変わっている。

| 時期 | 単元 | 工程 | Flow本文に残った痕跡 |
|---|---|---|---|
| 8/29〜9/3 | 二次関数 | 人間が骨格（見出し＋式＋短い断定文）を固定 → Codeが説明文を上に追加 | 骨格行と追加文の**二重記述**、見出しの言い換え、「①②③で」の手順語り |
| 9/7〜9/8 | 三角比 001〜021 | 同上、ただし説明文を抑制 | 式中心で密度は安定。符号判断には根拠あり（010・014） |
| 9/9〜9/11 | 三角比 022〜041 | 20問を一括教材化 | 平面図形の決定問題（022・023）は良いが、**空間図形（036〜038）で結果のみのステップが集中** |
| 9/16 | データの分析 | 検算バッチ側で説明文まで完成した状態で受領（Codeは説明文を書いていない） | 「したがって、〜は7。」の締め文が全ステップに付く、算術を1ステップにする、表を使う |

つまり、三角比が薄いのは「図形だから」だけではなく、**後半バッチで"結果を書けばFlowになる"状態まで削られた**ためであり、データの分析が濃く見えるのは「執筆者の文体（締め文）」と「問題タイプ」が重なったため。二次関数の中程度は、実は二重記述で水増しされた中程度である。

**3単元とも、Flow本文の密度基準が文書化されていなかった**（`_TEMPLATE_for_page_generation.md`は「見出し＋式が骨格、説明文はCodeが生成」としか言っていない）。ドリフトの根本原因はこれで、本レポートの第5〜6節がその基準になる。

## 4. 仮説の評価：「細かく分けるなら総量が増えてもよい」は成り立つか

**成り立つ条件がある。**

- 成り立っている例：DA-013（全ステップが判断1つ＋根拠1〜2文）、DA-020〜021（1ステップ1概念）、QF-028〜029（土台問題に1文の根拠）、TR-010（符号判断に象限の説明）。いずれも1ステップの散文は1〜3文だが、開くたびに新しい判断が1つ得られる。合計文字数は多くても「読み進める感覚」が軽い。
- 成り立っていない例：DA-012 (2)（分割したが各ステップに判断がない→8回開いて算術を8回見る）、QF-021（分割してあるが本文が前後のステップを語る→開くたびに同じ話）、QF-013〜020の二重記述（分割の中身が水増し）。

したがって仮説は次のように精緻化できる。

> 分割が認知負荷を下げるのは、**各ステップが「1つの判断」を持ち、本文がその判断のためだけに書かれている**ときに限る。判断のないステップは、開く回数の分だけ負荷を増やす。総量の上限を決めるのではなく、**ステップに判断がない限り本文を増やせない**というルールにすれば、総量は自然に適正に収まる。

中間層以下に有効という見立ては、上の条件付きで支持できる。三角比後半のように結果だけを並べたFlowは、中間層には「自分でやると途中で止まる」Flowになっており、逆に一番向いていない。

## 5. 「薄すぎる／適正／濃すぎる」の判定基準

文字数を使わず、ステップの中身で判定する。

### 5.1 薄すぎる（次のどれか1つでも該当）

1. **結果だけ**：数値・式の結果が書かれているが、それを出した式（定理の適用形、どの三角形・どの値を入れたか）が無い。例：TR-036 #1、TR-037 #1。
2. **一段飛ばし**：式Aから式Bへ、中間層が自力で埋められない変形を1行で飛んでいる（分数の分数の処理、二次方程式への整理、平方根の開き）。例：TR-016 (1)#2、TR-018 #2。
3. **判断に根拠がない**：☆・☆☆が付くステップ、または「2つのうちどちらか」「符号」「場合分けの境目」を決めるステップで、決めた理由が書かれていない。例：TR-019 #3。
4. **見出しの反復**：本文が見出しの言い換えだけで、式も根拠も足していない。例：QF-007 #1、QF-047 #3。

### 5.2 適正

- ステップに判断が**ちょうど1つ**ある。
- 本文は「何に何をするか」1文（見出しに書ききれない対象の指定）＋結果の式。判断が自明でない場合のみ根拠1文。中間層が飛べない変形は中間式1行。
- 前ステップとの接続は、式の受け渡し（前の結果が次の式に現れる）か、「〜より」「したがって」の接続語で足りる。前ステップを言葉で再説明しない。
- 散文は概ね0〜3文。0文でよいのは、式が判断を含まない計算だけのとき。

### 5.3 濃すぎる（次のどれか1つでも該当）

1. **判断ゼロの算術が独立ステップ**：掛け算・足し算・代入だけのステップ。前後のステップに吸収する。例：DA-012 (2)#2〜#3。
2. **前後のステップの語り**：「①で求めた」「②で確認した関係を当てはめる」「次に〜する」。例：QF-020、QF-021。
3. **二重記述**：同じ事実を骨格文と説明文で2回書いている。例：QF-013〜020の「ざっと描く」＋「下に凸で頂点は」。
4. **結論の言い直し**：式が答えを示した直後に、同じ内容を日本語で書く。例：DA-010 #3〜#4。
5. **検証の重複**：判断を出した後に、同じ判断をもう一度別の形で確認している。例：DA-005 #3の表の後半。
6. **定義・背景・別解**：そのステップの判断に不要な一般論。→ 問題メタ／解法メタ／補助Flowへ。

### 5.4 実務上の簡易チェック（制作・レビュー時）

各ステップについて次を順に問う。

1. このステップで生徒が**決めること**は何か → 答えが無ければ前後に吸収（濃すぎ）、2つ以上あれば分割。
2. その決定の**根拠**は本文にあるか → ☆付きで無ければ薄すぎ。
3. 本文から**見出しの言い換え**を消したら何が残るか → 式だけなら式だけにする。何も残らなければ薄すぎ。
4. 式の前後で**中間層が止まる変形**はないか → あれば中間式1行。
5. 本文に「①②③」「前のFlowで」「次に」があれば削る。
6. 式の直後の「したがって、〜は○○。」は、式が答えを示していれば削る。

## 6. 設計原則と、1ステップに書くもの・書かないもの

### 6.1 このサービス固有の設計原則

> **ThinkingFlowは「解説」ではなく「判断の記録」である。**
> **1Flow＝1判断。本文には、その判断を生徒がその場で自分の手で再現するために必要なものだけを書く。**
>
> 必要なもの＝（対象の指定）＋（結果の式）＋（自明でない判断の根拠1文）＋（飛べない変形の中間式1行）。
> それ以外——前後のFlowの説明、結果の言い直し、定義、別解、励まし——は、書く場所が別にある（問題メタ・解法メタ・補助Flow・最終解答）。
>
> **説明を増やしてよいのは、増える文が新しい判断か、判断の根拠であるときだけ。** 判断が増えないのに文が増えるなら、それは解説化であり、分割はそれを救わない。

これは「短く」ではなく「判断以外を書かない」という原則なので、判断問題（データの分析の読み取り）では自然に長くなり、計算問題（三角比の定理適用）では自然に短くなる。単元ごとに別基準を持つ必要がない。

### 6.2 1ステップに書くもの（実制作用）

| 要素 | 必須度 | 内容 |
|---|---|---|
| 見出し | 必須 | 判断の名前（動詞句）。「☆」はその判断が非自明なとき。 |
| 対象の指定 | 見出しで足りなければ | 「△ABCに余弦定理」「A群について」「右端x=aが頂点に届くか」。1文。 |
| 結果の式 | 必須（計算を伴うとき） | 定理の適用形 → 結果。中間層が一段で飛べない変形は中間式を1行足す。 |
| 判断の根拠 | ☆付き・採否・符号・境目のときは必須 | 1文。「A=120°よりB<60°なので」「係数の積が負なので符号が反転」。 |
| 表 | 判断を一覧にする問題のとき | 偏差表、候補表、5数要約。表の後に同じ内容を文で繰り返さない。 |

### 6.3 1ステップに書かないもの

- 見出しの言い換え（本文の1文目が見出しと同じなら削る）
- 前のFlowの再説明、次のFlowの予告、手順番号での自己参照（「①で」「③で分けた」）
- 式が示した結果の日本語での言い直し（「したがって、分散は7。」）
- 同じ判断の再確認・再検算
- 用語の定義・背景の理論・なぜその公式が成り立つか（→問題メタ・解法メタ。例外：問題の主題が手順そのものである場合の最小限の用語）
- 別解・確認ルート（→補助Flowを正式パターンにするなら補助Flow、そうでなければ解法メタ）
- 他の問題IDへの言及
- 励まし・難易度の所感（→問題メタ）

### 6.4 ステップの数

- 判断の数＝ステップの数。算術だけのステップは作らない（DA-012 (2)は5→3に減らせる）。
- 逆に、1ステップに判断が2つ（DA-017 #1：3つの散布図の判定を1ステップで）あるときは、分割を検討する。ただし「同じ判断を3回繰り返す」問題なら1ステップでもよい。
- 空間図形のように「面ごとに同じ定理を使う」問題は、ステップを増やすのではなく、1ステップの中で「どの面に何を使ったか」を式で示す（TR-036 #1をこの形にする）。
